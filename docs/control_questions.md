# Ответы на контрольные вопросы (ПЗ №1)

## 1. Чем отличается Git от GitHub?

**Git** — это локальная распределённая система контроля версий. Она работает
на компьютере разработчика и не требует интернета.

**GitHub** — это облачная платформа для хранения Git-репозиториев и
совместной работы. Она использует Git как основу, но добавляет веб-интерфейс,
issues, pull requests, actions и т.д.

Git — инструмент, GitHub — сервис.

## 2. Для чего используется виртуальное окружение Python?

Виртуальное окружение (`.venv`) — это изолированная среда Python, в которой
устанавливаются зависимости только для конкретного проекта.

Зачем нужно:
- разные проекты могут требовать разные версии одной библиотеки;
- не засоряется глобальный Python;
- зависимости легко воспроизвести через `requirements.txt`.

## 3. Что такое commit, branch, remote, pull request?

- **commit** — фиксация изменений в истории проекта с уникальным хешем и сообщением.
- **branch** — отдельная ветка разработки, позволяющая вести работу параллельно с основной веткой.
- **remote** — удалённый репозиторий (например, `origin` на GitHub).
- **pull request (PR)** — запрос на слияние изменений из одной ветки в другую, с возможностью code review.

## 4. Зачем нужен файл .gitignore?

`.gitignore` определяет, какие файлы и папки Git должен **игнорировать** —
то есть не добавлять в индекс и не коммитить.

Пример содержимого:
.venv/
pycache/
*.pyc
.env
.DS_Store

Это предотвращает попадание в репозиторий временных файлов, кэша,
секретов и виртуального окружения.

## 5. Как организовать командную работу над бизнес-приложением с помощью Git?

1. Создать общий репозиторий на GitHub.
2. Каждый разработчик клонирует репозиторий к себе (`git clone`).
3. Создаёт отдельную ветку под свою задачу (`git checkout -b feature/...`).
4. Делает коммиты и push в свою ветку.
5. Открывает Pull Request в `main`.
6. Второй разработчик проводит ревью, оставляет комментарии.
7. После исправлений — merge в `main`.
8. Все синхронизируют локальный `main` (`git pull origin main`).

## 6. Какие файлы обязательно должны быть в репозитории учебного проекта?

- `.gitignore` — исключения для Git.
- `README.md` — описание проекта, инструкция по запуску.
- `requirements.txt` — список зависимостей.
- `main.py` — точка входа.
- Папка `docs/` — проектная документация (бизнес-требования и т.п.).
- `.venv/` — **НЕ** должен быть в репозитории (он в `.gitignore`).

## 7. Что произойдёт, если два разработчика изменят один и тот же файл в разных ветках?

Возникнет **merge conflict** — конфликт слияния. Git не сможет автоматически
объединить изменения и пометит конфликтующие строки маркерами:
<<<<<<< HEAD
версия из текущей ветки
версия из другой ветки
||||||| feature/other

Разработчик должен вручную:
1. Открыть файл.
2. Выбрать нужные строки (или объединить обе версии).
3. Удалить маркеры конфликта.
4. Сохранить, `git add`, `git commit`.

После этого слияние завершится.
